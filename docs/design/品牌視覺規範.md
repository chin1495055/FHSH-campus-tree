# 品牌視覺規範（草稿）

> 狀態：**草稿，等 Saori 與 Qmoa 討論確認**（2026/10/20）
> 作品名稱還沒定（候選見下方），名稱定了之後再補 Logo 方向。
> 神獸的個別設定在 [神獸角色設定.md](神獸角色設定.md)。

## 核心價值：溫暖、守護、信仰（10/20 Qmoa 決定）

靈感來自台灣街頭最常見的一幕：廟埕的紅牆邊站著一棵老樹，樹蔭下有人走過；走進廟裡，抬頭是金色的雕刻和匾額。廟和樹，本來就是社區的中心。

| 核心價值 | 主色 | 來源 | 在作品裡代表 |
|---|---|---|---|
| **溫暖** | 廟紅 | 廟宇的紅牆 | 鄰里的人情味：大家一起關心身邊的樹，樹是鄰居、不是資料 |
| **守護** | 路樹綠 | 路邊撐起樹蔭的老樹 | 守住現有的樹：認養、回報、異動時一起發聲 |
| **信仰** | 廟金 | 廟裡雕刻、匾額的金色 | 台灣人敬樹的傳統：大樹公、參拜、給樹做契子 |

三個顏色一起出現，才是這個品牌。只有綠色會像一般環保網站，只有紅金會像廟宇網站。

## 品牌個性

一句話：**像住在巷口、會記得你的大樹公。**

| 是 | 不是 |
|---|---|
| 溫暖、親切、有點俏皮 | 說教、悲情、恐嚇 |
| 台灣在地、有人情味 | 日系或歐美的通用風格 |
| 尊重民間信仰 | 拿宗教開玩笑 |
| 以事實為準、對事不對人 | 攻擊市府或特定人物 |
| 大人小孩都看得懂 | 只有工程師或專家懂的術語 |

## 作品名稱（候選）

還沒定案，推薦：

1. **契樹囝**：最在地、最有溫度，和神獸、認養的設定最搭。
2. **台北樹不起**：最有態度，適合當 slogan 或 Demo 結尾。
3. **Send Tree 培**：Qmoa 提議。台語「搧喙䫌」（siàn tshuì-phué，賞巴掌）的諧音，英文讀起來是「送一棵樹」，加上「培養」的培，三種語言一次到位。
   - **建議用法**：當求救卡或分享按鈕的名字（分享本來就是 Send 出去），或當票選期間的口號，例如「台北的樹被砍，就是在搧我們的喙䫌。Send Tree 培，送一棵樹回來。」
   - **當主名稱的風險**：活動由競選辦公室主辦，容易被解讀成「賞市府巴掌」，和「對事不對人」的原則衝突；也和神獸的溫暖調性不太搭，不會台語的人也聽不出梗。
   - 如果要當主名稱，Demo 和 README 要先講清楚正面的意思：「Send Tree（送樹）＋培（培養）」。

4. **大樹神獸**：Qmoa 提議，也是目前文件、預覽頁和提案簡報用的暫定名稱。最直白，一聽就知道主角是神獸，和三隻神獸的角色設計直接連在一起；缺點是沒有諧音梗，記憶點要靠神獸本身。

其他候選：樹你最大、顧樹、樹位守護、樹於你、樹不清、神樹出沒、守樹待護。

已排除：樹可夢（模仿寶可夢名稱，有商標疑慮）。

## 色彩

### 三個主色

| 名稱 | 淺色模式 | 深色模式 | 代表 | 用途 |
|---|---|---|---|---|
| 廟紅 | `#B83A26` | `#E2705A` | 溫暖 | 品牌色塊、標題列、分享卡、大樹公的紅布；也用在求救 |
| 路樹綠 | `#2F5D3A` | `#6DB58A` | 守護 | 主要按鈕（守護這棵樹）、連結、正常狀態 |
| 廟金 | `#C49A3C` | `#D9B25A` | 信仰 | 參拜、神獸外框、稀有、成就。**只當底色**，上面放墨色字 |

### 材質：三個主色不是平面色塊（10/20 Qmoa 決定）

三個主色要帶有真實生活裡摸得到的質感，讓畫面像台灣的街頭和廟裡，而不是一般 App 的平面色塊。

| 主色 | 材質 | 看得到的細節 | 來源（CC0，可自由使用） |
|---|---|---|---|
| 廟紅 | **斑駁的紅牆** | 灰泥筆觸、刮痕、零星剝落，下緣比較深像雨痕 | [ambientCG PaintedPlaster001](https://ambientcg.com/view?id=PaintedPlaster001) |
| 路樹綠 | **苔蘚** | 細密的顆粒和凹凸，加一點樹葉間的光 | [ambientCG Moss002](https://ambientcg.com/view?id=Moss002) |
| 廟金 | **金箔** | 一方一方的金箔接縫、皺褶、凹凸反光；滑過去時反光會移動 | [ambientCG Metal042A](https://ambientcg.com/view?id=Metal042A)，另外加上方格接縫 |

做法：用原始材質的明暗和法線圖（記錄凹凸的貼圖）重新上色成品牌色，淺色、深色模式各一張，512×512 WebP，每張 60～140 KB，以 256px 重複鋪滿。程式雜訊做的版本（10/20 第一版）看起來像迷彩，已經換掉。

**使用規則**：

- **只用在大色塊**：標題列、分享卡、神獸外框、參拜按鈕、簡報的色塊頁。卡片內文、表單、地圖底圖用素色。
- **文字要看得清楚**：材質會讓背景深淺不一。廟紅、路樹綠材質上的字用白色加淡淡的文字陰影；廟金材質上的字用墨色。小於 16px 的字不要直接放在材質上。
- **狀態標示維持素色**：狀態標籤、求救標示不加材質，警示才看得清楚。
- **動態**：只有金箔的反光會動，使用者手機設定「減少動態」時要關掉。
- **效能**：六張貼圖合計約 590 KB，手機上只載入目前主題的三張。
- **授權**：ambientCG 的材質是 CC0，可自由使用、不用標註，但 README 仍寫明來源。
- 範例和程式寫法在品牌視覺預覽頁的 Material 元件（目前只有 Qmoa 看得到）。

### 樹木狀態色

| 狀態 | 淺色模式 | 深色模式 | 圖示 |
|---|---|---|---|
| 正常 | `#2F5D3A`（路樹綠） | `#6DB58A` | 葉子 |
| 需關注 | `#8A6400` | `#E8B84A` | 驚嘆號 |
| 公示中 | `#A9531A` | `#EE9550` | 公告牌 |
| 求救／即將移除 | `#B83A26`（廟紅） | `#E2705A` | 紅布旗 |
| 保留／移植 | `#2F66A8` | `#7FAEE6` | 盾牌 |

**狀態不能只靠顏色表示**，一定要搭配圖示和文字（例如「公示中」三個字）。色弱的人分不出紅綠，戶外陽光下手機螢幕也看不清顏色。需關注、公示中、求救三個都是暖色，更要靠圖示和文字分辨。

### 注意

- **廟紅同時是品牌色和求救色**：平常用在大面積的品牌色塊（像紅牆一樣安靜），求救時一定加上紅布旗圖示和「求救」文字，必要時加一點晃動動畫，才不會跟一般的紅色區塊搞混。
- **廟金當文字太淡**（對比只有 2.4:1），只能當底色或外框，上面放墨色字。
- 綠色也接近政黨的代表色。三個主色一起用，不要做成一片綠。
- 上面的色碼都檢查過文字對比（一般文字至少 4.5:1）。改色碼時要重新檢查。
- 最終色碼寫進程式前，要用對比檢查工具確認文字可讀（一般文字對比至少 4.5:1）。
- 要支援深色模式的話，由 Saori 決定是否在 MVP 範圍內。

## 插圖風格

### 方向：3D 公仔風（10/20 Qmoa 決定）

神獸用 **3D 立體角色**呈現，分兩種用法：

| | 3D 風格的圖片（主要） | 可轉動的 3D 模型（只做 1 隻） |
|---|---|---|
| 用在哪裡 | 地圖圖示、神獸卡、分享卡、圖鑑，全部 | Demo 主角鬚鬚公的神獸頁，手指可以轉動、會呼吸晃動 |
| 怎麼做 | AI 生圖工具產出 3D 渲染風格的圖片 | AI 轉 3D 工具（例如 Meshy、Tripo），或 Claude 用程式碼拼出簡單造型（做法和 Saori 討論決定） |
| 優先 | P0 | P1 |
| 注意 | 一張幾百 KB，不會拖慢 PWA | 模型檔要壓縮到 2 MB 以內，等主畫面載入完才載入，手機才不會卡 |

AR（用相機看到神獸站在樹旁邊）不做，放進簡報當未來規劃。

### 原則

- **Q 版、圓潤**：2～3 頭身，造型圓滾滾，沒有尖角。
- **軟膠公仔質感**：像桌上的小公仔或軟膠玩具，表面霧面、微微柔光，不要太寫實。
- **統一的打光和鏡頭**：全部神獸用同一個光源方向（左上方柔光）、同一個鏡頭角度（正面稍微俯視）、同一個米白色背景。這樣 5 隻放在一起，才像同一個世界。
- **輪廓要簡單**：縮小成 48×48 的地圖圖示時，3D 的細節會糊掉，要靠輪廓認出是哪隻神獸。
- **一眼看出是哪種樹**：每隻神獸都從真實樹種的特徵變形而來，例如榕樹的氣根變成鬍鬚。
- **加入台灣廟宇元素**：紅布、平安符、香火金光、燈籠，點到為止。
- **所有神獸同一套比例、材質、配色規則**。

### 避免

- **模仿現有 IP**：不要做成寶可夢、皮克敏、動物森友會或其他現有角色的樣子。3D 公仔風特別容易撞到這些作品的風格，產圖後要檢查。
- **恐怖或鬼怪感**：台灣也有「大榕樹下有鬼」的傳說，神獸要可愛，不要陰森。
- **畫出具體的神明**：不要畫成土地公、媽祖等真實神明的樣子，神獸是樹的化身，不是神明本人。
- **傷樹的畫面**：不要出現在樹上釘東西、用鐵絲纏繞、在樹根旁燒香燒金紙的畫面。

## 語氣與文案

- **台灣口語**：「這棵樹需要你」，不要寫成「該樹木需要您的關注」。
- **可以點綴台語**，但一句最多一個詞，而且要確認用法正確，例如「呷飽未？」「顧樹」。
- **對事不對人**：寫「這棵樹被公告要移除」，不要寫「市府又要砍樹了」。
- **模擬資料要說清楚**：「示範資料」「模擬情境」的標示要看得到，不要藏在小字裡。

### 文案範例

| 情境 | 這樣寫 | 不要這樣寫 |
|---|---|---|
| 首頁 | 你家附近有 12 棵樹，有 3 隻大樹神獸 | 歡迎使用樹木守護平台 |
| 守護成功 | 你成為鬚鬚公的第 129 位守護者 | 守護成功 |
| 需要關心 | 鬚鬚公最近沒什麼元氣，可以去看看它嗎？ | 警告：樹木健康異常 |
| 公示中 | 這棵樹被公告要移除，原因是公共工程。你可以…… | 市府又要砍樹了！ |
| 回報完成 | 謝謝你！這是市民觀察紀錄，不是專業診斷 | 診斷完成：疑似褐根病 |

## 製作方式

- **簡單的圖示**（地圖圖示、App 圖示）：可以請 Claude 畫成 SVG 向量圖，直接放進網頁。
- **神獸角色（3D 風格圖片）**：由 Claude 依角色設定寫繪圖提示詞，交給 AI 生圖工具（例如 Gemini）產出 3D 渲染風格的圖，再挑選、去背、修整。
- **鬚鬚公 3D 模型**：用 AI 轉 3D 工具，或由 Claude 用程式碼拼出造型。要用哪一種、網頁用什麼套件顯示（例如 three.js 或 model-viewer），由 Saori 與 Qmoa 討論決定。
- 用到的 AI 工具都要記在 README（比賽規則）。
- **什麼時候開始畫**：比賽規則寫「Day 1（10/23）起可開始討論與寫程式」，10/23 前能不能先畫圖要先問主辦單位。這份規範和角色設定是規劃文件，可以先寫。
