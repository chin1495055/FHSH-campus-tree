## 1｜Brief

| 項目 | 內容 |
|---|---|
| **一句話** | 觀眾看完要記得：**台北每棵樹都可以有一群鄰居守著，樹出事時大家會第一時間知道。** |
| 觀眾 | 審核人員（確認 MVP 真的能用）、票選期間的一般市民（要看得懂、想分享） |
| 長度 | 約 2 分 43 秒（建議 2～3 分鐘） |
| 格式 | 主版 16:9（YouTube）。9:16 直式版之後票選拉票再做，不在 15:00 前的範圍 |
| 聲音 | 先只放字幕；音樂上傳 YouTube 後從音效庫加，配音之後再決定 |
| 語言 | 繁體中文，字幕用全形標點 |

### 只能用的真實素材

- **App 實機錄影**：Day 2 程式定版後，用手機螢幕錄影錄下來。這是影片的主體。
- **Logo、神獸圖、配色、字體**：只用 [design-system](../../design-system/README.md) 裡的檔案。
- **動畫段落**：做在影片畫布上，用的是 Day 1 簡報的插圖、街景和 design-system 的神獸圖。
- **分享卡**：用 App 實際產生的守護籤、求援籤 PNG。

### 視覺規則

- **保留**：design-system 的宣紙米白底、樹綠、墨線、平塗；廟牆紅只出現在「守護祂」按鈕。
- **避免**：置中大字配漸層背景、所有東西都淡入、emoji、「抽」「稀有」這類抽卡用語。
- **不編造**：App 段落只放真的做出來、真的能操作的畫面。P1 沒做出來的功能（例如市府端查詢、圖鑑）就不放，不要用設計稿假裝成成品。
- **事實**：真實案例只用一句話帶過，說法跟簡報第 2 頁一樣。不放新聞截圖或真實人物照片（著作權、肖像權）；不點名任何人。
- **模擬資料要標示**：守護人數、回報紀錄、異動公告都是模擬的，片尾字幕寫清楚「樹木位置與樹種為臺北市開放資料，其餘為模擬資料」。

用「畫面狀態」來寫，每一段都有進入狀態、離開狀態和存在的理由。旁白不照唸畫面上的字。

|---|---|---|---|---|---|

| 2 | 0:14–0:34 | 理念與願景＋為什麼從市民做起 | 三張理由卡依序出現 → 願景大字；下方行人走過行道樹、停下來看樹 | 畫布動畫 | 說出我們相信什麼，以及為什麼主角是市民、為什麼先守住老樹 |
| 3 | 0:34–0:46 | 設計元素與概念 | 「設計元素與概念」→ 文化、故事、信仰三張卡片 → 燈海亮起 | 畫布動畫 | 說明設計怎麼溝通台灣的文化、故事和信仰，作品不只是工具 |

逐句字幕與時間見 [腳本與字幕.md](腳本與字幕.md)，合計約 467 字，每秒不到 3 字。

### 實機錄影的操作路徑

Day 2 錄影時照這個順序點，不要即興：

```
0:56 打開 App（地圖首頁）→ 點鬚鬚公的神獸標記
1:08 神獸頁 → 按「守護祂」→ 選「在地守護」
1:20 按「回報樹況」→ 拍照（用預設照片）→ 勾「枝葉稀疏」「樹穴被填」→ 送出 → 看到「你點亮了一盞燈」
1:38 觸發模擬的異動通知 → 打開異動警報
1:50 按分享 → 跳出求援籤
2:02（有做的話）回到神獸頁 → 社區佈告欄
2:12 結束錄影
```

- 錄之前先清掉瀏覽器的 localStorage，讓守護人數和回報次數從預設值開始。
- 手機調成勿擾模式、電量和時間不要太難看；字級用預設大小。
- 時間是畫面上的時間；手機錄影從 0:56 開始播，所以錄影的第 0 秒對到畫面的 0:56。每一步大約停 10 秒，字幕才對得上。
- 錄影總長約 76 秒。某一步沒做出來就跳過，最後幾秒留在最後一個畫面就好。

## 3｜剪輯方式

> **10/24 更新**：團隊沒有人會剪片，改用「不用剪輯」的做法：動畫段落已經做在影片畫布上，App 段落用手機錄影放進畫布，整支用 QuickTime 螢幕錄影錄下來。步驟見 [腳本與字幕.md](腳本與字幕.md)。下面的 iMovie 做法留作備案。

- **工具**：iMovie（Mac 內建）就夠。不需要架 Remotion 之類的影片框架。
- **版面**：16:9 畫面，宣紙米白底，手機錄影放在中間或偏右，左邊放這一段的字幕標題（例如「① 守護」「② 回報」「③ 異動警報」）。
- **片頭片尾**：在 Mac 上開 Day 1 簡報，用 QuickTime「新增螢幕錄製」錄指定區域，1920×1080。動畫是進到該頁自動播放，錄的時候按一下換頁就好。
- **音樂**：用 YouTube 音效庫或其他明確標示免版稅的音樂，記下曲名和授權，寫進 README。不要用流行歌，YouTube 可能因版權擋片，審核就過不了。
- **剪接點對拍子**：換段落的地方對在音樂的重拍上；按「守護祂」、送出回報這種動作，可以加一聲輕的點擊音效。

## 4｜匯出前的畫格檢查

先不要反覆看整支影片。每一段各截一張關鍵畫格，排在一起檢查：

- [ ] 前 2 秒就有畫面變化，不是靜止的標題
- [ ] 字在手機上看得清楚（YouTube 很多人用手機看）
- [ ] 手機錄影裡的字沒有被字幕或邊框擋到
- [ ] App 畫面全部是真的實機錄影，沒有拿設計稿冒充
- [ ] 神獸名字都是鬚鬚公、茄苳仔、雀雀（設計稿的舊名字不要出現）
- [ ] 配色、字體前後一致，沒有出現 design-system 以外的顏色
- [ ] 換段落的地方沒有卡在半透明、半移動的難看畫格
- [ ] 音樂和剪接點對得上；關掉畫面只聽聲音，也聽得出段落
- [ ] 片尾有標示真實資料與模擬資料
- [ ] 最後一格可以當 YouTube 封面

找出問題時，先挑最嚴重的三個，寫下「時間點、哪裡不對、怎麼改」，只改那三段再匯出一次。

## 6｜待決定

3. **字幕用哪一種？** 畫面字幕（預設）或 YouTube 的 `.srt`，二選一。
4. **要不要配音、加音樂？** 先只放字幕最保險；音樂上傳後從 YouTube 音效庫加。
