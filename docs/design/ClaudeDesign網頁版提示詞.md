# Claude Design 提示詞：關鍵畫面網頁版（桌機寬螢幕）

> 用途：整段貼進 Claude Design，請它把現有的手機版關鍵畫面延伸成桌機網頁版。
> 狀態：草稿（2026/10/23，Qmoa）。產出後放回 `docs/design/`，再跟 Saori 確認要不要做進 App。
> 背景：票選期間很多人會在電腦上點開分享連結，手機版畫面直接放大在寬螢幕上會很空，要有一套桌機版的排法。

---

## 提示詞（從這裡開始複製）

請把現有「大樹神獸」的 16 個手機版關鍵畫面，延伸出一套**桌機網頁版**。這是同一個 App 的響應式版本，不是另一個產品：**沿用既有的設計系統（tokens、元件、命名、視覺風格），不要重新設計，手機版畫面也不要改動。**

### 參考檔案（請先看過再開始）

- **「大樹神獸 關鍵畫面」**：現有的 16 個手機版畫面。桌機版的內容、文案、元件、資訊順序都以這份為準，只改排版，不要重新發想內容。下面每個畫面都標了對應的頁碼。
- **「大樹神獸」設計系統**：`tokens.css`、`components.css`、`components/*.md`、`assets/`。
- 畫面裡沒有的狀態（例如上傳照片），請用設計系統現有的元件組出來，不要新造風格。

### 作品是什麼（簡短）

「大樹神獸」是台北市政黑客松的作品。市民用遊戲的方式守護家附近的樹：每棵樹都有一群鄰居看著，樹要被移除前大家都會知道，誤砍就不容易發生。大型老樹會化身「神獸」，有名字、個性和來歷。

### 桌機版的使用情境

- 主要是**票選期間從 LINE、Threads、FB 點開分享連結的訪客**，以及**在家用電腦整理回報的守護者**。
- 第一眼要看懂三件事：這棵樹是誰、有多少鄰居在守護祂、我可以怎麼幫忙。
- **電腦上沒有掃描功能**，這是桌機版和手機版唯一的功能差異。其他功能（包括在地守護和回報）電腦上都能用。
- 「在地守護」的意思是**家附近、常經過的樹**，由使用者自己選，不靠掃碼驗證。「遠端關注」是不住附近、但想關心這棵樹的人。
- 回報可以**回家再上傳照片**：在樹旁邊用手機拍，回家用電腦選照片、填健康檢查。

### 技術限制（很重要）

- App 是純前端靜態網站：HTML、CSS、原生 JavaScript，**不用 React 或任何框架，不用建置工具**。地圖用 Leaflet。
- 桌機版用 **media query 加在現有的 `components.css`**，例如 `@media (min-width: 1024px)`。不要另外做一套 class，也不要複製一份手機版的 HTML。
- 斷點：手機（小於 768px）維持現狀；平板（768–1023px）可以先沿用手機版、置中加寬；桌機（1024px 以上）用下面的排法。
- 顏色、尺寸、線寬、圓角只能用 `tokens.css` 的 CSS 變數，不要寫死色碼。class 一律用 `dsh-` 開頭。
- 全系統平面：不加陰影、不用漸層、不用 emoji。
- 內容最大寬度請定一個 token（例如 `--content-max`），超寬螢幕時置中，兩側留宣紙米白底。

### 各畫面的桌機排法

1. **頂部導覽**：手機的底部導覽列（地圖、圖鑑、掃描、通知、我的）在桌機改成頂部橫列，左邊放「大樹神獸」橫式標誌。**桌機版拿掉「掃描」**，只留地圖、圖鑑、通知、我的；找樹改用地圖和搜尋框（可以輸入樹名、樹號或地點）。
2. **地圖首頁**（第 1 頁）：地圖佔大部分畫面。左側固定一欄放搜尋框、篩選（全部、神獸、需關注、公示中）和附近的樹清單。點樹之後，手機版的底部卡片在桌機改成**右側面板**，地圖不會被蓋住。
3. **神獸頁**（第 2、3 頁）：左右兩欄。左欄放神獸大圖、名字匾額、狀態、燈海（守護人數）和「守護祂」按鈕；右欄放祂的故事、小知識、最近的回報。廟牆紅還是只給「守護祂」，一個畫面只有一個紅按鈕。
4. **守護祂（選在地守護／遠端關注）**（第 2 頁的按鈕，選擇畫面原本沒有）：改成置中的對話框，兩個選項並排。「在地守護」寫「這是我家附近、常經過的樹」，「遠端關注」寫「在遠方，收到祂的消息」。不要求掃碼、不問地址。
5. **回報三步驟（上傳照片、健康檢查、點亮一盞燈）**（第 4、5、6 頁）：桌機上三個步驟可以排在同一頁，左邊照片、右邊檢查清單，最後點燈。
   - 步驟 1 從「拍照」改成「**上傳照片**」：可以拖曳或選檔，一次多張，顯示縮圖。附一個「拍攝日期」欄位（預設今天，可以改），讓人知道照片是哪天在樹旁拍的。
   - 上傳區旁邊一行小字：「照片的位置資訊會在上傳前移除」。
   - 健康檢查清單（褐根病徵兆等）和點亮一盞燈的完成畫面，照手機版的內容和元件。
6. **異動警報**（第 7 頁）：左右兩欄，左邊是公示內容（原因、管理單位、倒數天數、說明會時間），右邊是守護人數和「分享這張求救卡」。公示中的橘黑斜紋警報維持原樣，不做成按鈕。
7. **社區佈告欄與活動**（第 8、9、10 頁）：活動卡片排成兩到三欄的格狀；留言區放在右側或下方。
8. **圖鑑**（第 11、12 頁）：卡片格狀排列，每排四到六張，分「在地守護」和「遠端關注」兩區。神獸卡和一般樹卡的大小區分要比手機版更明顯。空白狀態的「掃描樹牌 QR code」按鈕在桌機改成「去地圖找樹」。
9. **分享卡與 OG 圖**（第 13～16 頁）：分享卡（1080×1350）和 OG（1200×630）的圖本身不變。桌機上的分享頁改成「左邊預覽圖、右邊動作」：複製連結、下載圖片、分享到 LINE、Threads、FB。IG 在桌機上不能直接分享，改成「下載圖片後用手機上傳」。

### 文案規則

- 神獸名字：**鬚鬚公**（榕樹）、**茄苳仔**（茄苳）、**雀雀**（雀榕）。設計稿裡的「雀雀阿嬤」和「雀雀兄」是彩蛋角色，保留不要改。
- 樹和神獸一律用「**祂**」稱呼，不用「它」或「牠」。按鈕寫「守護祂」，分享卡寫「我在守護祂」。
- 繁體中文、台灣用語、全形標點。
- 模擬的人名、地址要明顯是假的；地點佔位字維持「［所在街道］」的寫法。

### 不要做的事

- 不要改神獸的名字、角色圖、手機版畫面或已完成的元件。
- 桌機版不要出現任何掃描、開相機的按鈕或提示，也不要顯示「加到主畫面」的提示。
- 不要做抽卡、星等、閃光這類暗示收集稀有度的設計，也不要個人排行榜。
- 不要用紅色表示任何樹況；紅色只給「守護祂」按鈕。
- 不要在畫面上顯示守護者的位置、住家或散步路線。守護人數只顯示數字。
