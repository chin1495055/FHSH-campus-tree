# PRD：大樹神獸（第一版）

> 狀態：**第一版草稿，等 Saori 與 Qmoa 確認**（2026/10/23）
> 依據：[MVP.md](MVP.md)、[市民優先 User Stories](市民優先_User_Stories.md)、[10/20 分工與 MVP 範圍會議](../discussion-notes/2026-10-20-分工與MVP範圍會議.md)、[關鍵畫面設計稿](../design/大樹神獸關鍵畫面.html)（16 頁）、[design-system](../../design-system/README.md)、`data/` 底下的開放資料與模擬資料。
> 這份文件把上面幾份整理成「要做哪些畫面、每個畫面要能做什麼、怎樣算做完」。文件之間對不上的地方，列在最後的「待決事項」。

## 1. 一句話

讓市民用遊戲的方式守護家附近的樹：每棵樹都有一群鄰居看著，樹要被移除前大家都會知道，誤砍就不容易發生。

> 新加坡讓每棵樹都有身分證，我們讓每棵樹都有一群鄰居。

## 2. 要解決的問題

| 現況 | 例子 | 我們的切入點 |
|---|---|---|
| 樹不見了才發現 | 美崙公園紀念樹 4 月移除，10 月才有人發現 | 樹有異動，守護者馬上知道 |
| 工程現場沒人即時看到 | 東門茄苳被誤砍、建中樹穴被水泥填塞 | 在地守護者回報「樹旁出現施工」「樹穴被填」 |
| 病害發現太晚 | 松菸老雀榕因褐根病枯死 | 回報表單引導市民檢查褐根病的早期徵兆 |
| 分不清是誰的樹、為什麼移 | 市府說明有四大原因，民眾常誤會 | 每棵樹顯示管理單位，異動顯示原因分類 |

「哪裡有樹、哪裡能種、砍了多少」已經有人做了（Tree Radar、台北樹跡、樹冠觀測等），**還沒有人處理「為什麼會誤砍」**。我們的核心論點：小樹的樹冠要很多年才長得回來，**先守住現有的大樹**比事後補種更重要。

作品以事實為準、並列市府的說明，重點放在改善流程，不攻擊特定人。

## 3. 目標與成功指標

### 這次黑客松的目標

1. **10/24 14:00 定版**一個手機上能實際操作的 PWA，15:00 前連同 YouTube 影片和「未來需要的資源」通過審核。
2. **2 分鐘 Demo** 能順順走完主線：找到樹 → 守護祂 → 回報狀態 → 樹出事時大家一起發聲。
3. **票選期間**（10/24–10/31）訪客用手機點開分享連結，兩分鐘內看懂、願意按「守護祂」和分享。

### 怎樣算成功

| 指標 | 目標 |
|---|---|
| Demo 主線 | 不用解說也能一路點完，中間不卡、不出錯 |
| 首次載入 | 手機 4G 下 3 秒內看到地圖 |
| 分享預覽 | 貼到 LINE、Threads 都有正確的標題和預覽圖 |
| 加到主畫面 | iPhone、Android 都實測過 |
| 資料透明 | 每個畫面的模擬內容都有標示，沒有人會以為已接上市府系統 |

## 4. 使用者

| 角色 | 是誰 | 能做什麼 |
|---|---|---|
| **在地守護者**（主動） | 住附近、常經過的人 | 自己選「家附近、常經過的樹」、回報樹況（可回家上傳照片）、發起樹下活動 |
| **遠端關注者**（被動） | 不住附近，甚至不在台北，但在乎這棵樹或這個樹種 | 追蹤、收到異動和活動消息、按「我想參加」、分享 |

- 這是兩種參與方式，不是兩種帳號，同一個人可以兩種都有。
- **這次不做**：市府／維護人員端（市府端查詢列 P1，當 Demo 收尾彩蛋）、親子同行者。

## 7. 功能需求

每個功能列出「要能做什麼」和「怎樣算做完」。完整的 Given／When／Then 在 User Stories，這裡只寫實作時要注意的重點。

### F1 地圖首頁（關鍵畫面第 1 頁）

**要能做什麼**

- 打開就是地圖，不用登入、不用註冊。
- 地圖固定以競選總部（中正區北平東路 30-1 號）為中心，**不做真正的定位**（10/20 會議決定）。
- 顯示 `data/trees.json` 的 296 棵樹（真實開放資料，總部半徑 300 公尺）。
- 標記：一般樹用小屋簷標記；神獸放大 1.5 倍、加金色光圈、小金匾和神獸小圖，旁邊顯示守護人數。公示中的樹在標記上加「公示中」標籤。
- 上方篩選膠囊：全部／神獸／需關注／公示中。
- 點標記，底部卡片顯示：名字、狀態標籤、樹種・樹齡・距離、「○○ 位鄰居守護」，點卡片進樹木頁。
- 底部導覽列：地圖／圖鑑／掃描（中間大鍵）／通知／我的。

**怎樣算做完**

- 手機上兩指縮放、拖曳順暢，296 棵不需要群聚。
- 篩選後地圖只剩對應的樹。
- 地圖底圖的出處（CARTO、OpenStreetMap）有標示。

### F2 樹木頁／神獸頁（關鍵畫面第 2、3 頁）

**要能做什麼**

- 從地圖、分享連結（`#/tree/樹號`）、掃 QR code 都能打開同一頁。
- **上半**：受保護樹木標示、神獸名字與圖、樹種・樹齡・所在街道、狀態標籤、管理單位、元氣條（數字＋文字，如「78 茂盛」）、燈海卡（守護總人數，分成在地守護／遠端關注）。
- **下滑**：在地故事（附「由 ○ 位鄰居提供」與「補充故事」入口）、樹的檔案（樹種、樹齡、樹圍、身分、管理單位、樹籍編號）、最近回報。
- 底部固定兩個按鈕：「回報樹況」（次要）、「守護祂」（主要，廟牆紅，一個畫面只有這一個紅按鈕）。
- 有異動公告時，頁面頂端出現公示中提醒條，點了進異動警報。
- 非神獸的一般樹也要有樹木頁：沒有名字、故事和神獸圖，其他欄位一樣（**設計稿沒有這頁，照神獸頁簡化**）。

**怎樣算做完**

- 沒有資料的欄位顯示「資料未提供」或不顯示，不自己推測。
- 樹齡是用胸徑粗估的，要標「推估」；管理單位是推定的，要標「推定」（`trees.json` 的 `ageEstimated`、`managerEstimated`）。
- 神獸名字、個性、故事標示「創作內容」；狀態、元氣、守護人數標示「模擬」。真實資料（樹號、樹種、位置）和模擬內容分開呈現。
- 元氣不描述成專業健康診斷。

### F3 守護祂

**要能做什麼**

- 按「守護祂」後選「在地守護」或「遠端關注」，各附一句說明（「這是我家附近、常經過的樹」／「在遠方，收到祂的消息」）。
- 選完，燈海人數 +1 並有亮燈動畫，按鈕變成「已守護」。
- **在地守護由使用者自己選，不靠掃碼驗證**（10/23 Qmoa 與 Saori 確認）。不問地址、不記錄位置。
- 守護狀態存在 localStorage，重新整理還在。

**怎樣算做完**

- 不要求住址、不要求登入。
- 公開畫面只看得到人數，看不到誰在守護。
- 守護人數 = 模擬的基礎人數 ＋ 自己按的那一下。

### F4 掃描 QR code

**要能做什麼**

- 底部導覽列中間的「掃描」打開相機，即時辨識 QR code（`qr-scanner` 套件，iPhone Safari 也能用）。
- QR code 內容是網址 `https://…/#/tree/樹號`，用手機內建相機掃也能直接打開。
- 掃到有效樹號：打開樹木頁。掃碼只是快速找到樹的入口，不再拿來驗證在地身分（10/23 改）。
- 掃不到或樹號不存在：顯示看得懂的錯誤和「回到地圖」，不捏造樹木資料。
- 拒絕相機權限：提示可以改用手機內建相機掃，或回地圖找樹。
- **電腦版（1024px 以上）沒有掃描**：導覽列拿掉「掃描」，找樹改用搜尋和地圖。版面見 `design-system/desktop.css` 和 Claude Design 畫布「大樹神獸 桌機網頁版」。

**怎樣算做完**

- Demo 的 3 棵神獸各印一張模擬 QR code，實測掃得到。
- 不掃描、不抓取市府的任何系統。

### F5 回報樹況（關鍵畫面第 4、5、6 頁）

開放給在地守護者。遠端關注者按「回報樹況」時，提示可以改成在地守護。照片可以在樹旁拍，也可以回家再上傳（10/23 改）。

**步驟 1／3：拍照**

- App 內的取景框（虛線框、「把樹幹和樹冠都拍進框裡」、快門鍵），用 `getUserMedia`。時間不夠退回 `<input capture>`。
- 建議拍：全貌、樹幹基部、樹穴，拍過的打勾。
- 照片可以略過；拒絕相機權限時一樣能進下一步。
- 也可以「上傳照片」（`<input type="file" multiple>`）：電腦版只有這個選項，可以拖曳、一次多張。附「拍攝日期」欄位（預設今天，可以改）。
- 上傳前移除照片的位置資訊（EXIF GPS），畫面寫「照片的位置資訊會在上傳前移除」。用 canvas 重畫縮圖時 EXIF 會自然消失。
- 照片用 canvas 縮到約 800px，只存 IndexedDB 或只預覽，不塞 localStorage。

**步驟 2／3：健康檢查**（可複選）

| 項目 | 說明文字 | 欄位（`mock_reports.json`） |
|---|---|---|
| 根盤隆起 | 樹根把地面或人行道撐起、裂開 | `rootBulge` |
| 樹幹網狀格紋 | 樹幹基部有褐色網狀紋路，可能是褐根病 | `trunkNetPattern` |
| 枝葉稀疏 | 葉子變少、轉黃，或枯枝變多 | `sparseLeaves` |
| 施工公告 | 樹附近貼了施工、移植或移除公告 | `constructionNotice` |
| 樹穴被填 | 樹根周圍被水泥、地磚或雜物蓋住 | `pitFilled` |
| 都沒有，看起來很健康 | 和上面五項互斥 | — |

- 送出鈕顯示勾了幾項：「送出回報（2 項狀況）」。一項都沒勾時不能送出，並提示要勾哪裡。

**步驟 3／3：點亮一盞燈**

- 神獸說一句話（例如「謝謝你來看我，樹穴的事我記下了。」）。
- 燈海人數跳動：128 → 129 盞。
- 「接下來會發生什麼」：列出這次回報的狀況。有狀況時，樹木狀態改成「需關注」、元氣下降、神獸換成「需要關心」的圖。
- 累計成就：「這是你的第 ○ 次回報・一起守護的第 ○ 天」。
- 按鈕：回到地圖、分享給鄰居（進 F9）。
- 回報出現在樹木頁的「最近回報」，存 localStorage。

**怎樣算做完**

- 明確寫「這是市民觀察，不是專業診斷」。
- 不能寫成「已送給管理單位」，因為沒有串接；改成「Demo 模擬：正式上線後會轉給管理單位」（見待決事項 6）。
- 不記錄回報者的位置。

### F6 社區佈告欄與發起活動（關鍵畫面第 8、9、10 頁）

**要能做什麼**

- 樹木頁有「社區佈告欄」，顯示樹下的市民活動卡，依活動日期由近到遠排列。頂端摘要「本月 ○ 場活動・○ 人想參加」。
- 活動卡：撕頁日期、「市民活動」籤、標題、時間、地點、說明、發起人、想參加人數、「我想參加」。
- **在地守護者**看得到「在樹下發起活動」，填活動名稱、日期、時間、說明；地點固定為「○○樹下」；發起人預設「在地守護者（匿名）」，可選顯示暱稱。
- **遠端關注者**看不到發起按鈕，改顯示「這是你家附近的樹的話，改成在地守護就能發起活動」，但可以按「我想參加」。
- 發起前提醒：不要寫別人的姓名、電話等個資，活動選在公開場所。

**怎樣算做完**

- 活動卡是綠色系，不用橘色斜紋和紅色按鈕，和官方異動公告一眼分得出來。
- 卡片標示「市民活動」，不會被誤認成市府公告。
- 預設資料是模擬的並標示；自己發的活動存 localStorage，只有自己看得到。

### F7 我的守護圖鑑（關鍵畫面第 11、12 頁）

**要能做什麼**

- 標題下註明「只有你看得到」。
- 分兩區：**在地守護 ○ 棵**（大卡片：神獸圖、名字、樹種、樹號、狀態）、**遠端關注 ○ 棵**（小列表）。
- 老樹或受保護的樹用特別樣式（雲紋深綠底），一般行道樹也有自己的卡。
- 卡片右上角提醒標記：「異動公告」「新活動 2」。
- 點卡片打開樹木頁。
- 空白狀態：「你還沒有守護任何一棵樹」＋「去地圖找樹」「掃描樹牌 QR code」（電腦版只有「去地圖找樹」）。

**怎樣算做完**

- 選了「在地守護」的樹進「在地守護」區。
- 圖鑑不公開、不能分享整本，分享單張時照 F9 的隱私規則。

### F8 異動警報（關鍵畫面第 7 頁）

**要能做什麼**

- 用一個模擬公示事件（`mock_notices.json` 的 `N-MOCK-001`）把 Demo 主角的狀態改成「公示中」。
- 通知頁出現一則「你守護的樹進入公示」，點了進異動警報（**通知頁設計稿沒有，做最簡單的列表**）。
- 異動警報頁：
  - 頂端橘黑斜紋警示、「預計移除，期限前可以表達意見」、倒數天數。
  - 樹的小卡（名字、樹種、樹齡、地點、公示中標籤）。
  - 移除原因分類，亮起這次的類別。
  - 異動公告明細：公告字號、處理方式、原因、管理單位、申請單位、意見截止。
  - 「○○ 的 ○ 位守護者都收到了這則警報」。
  - 按鈕：「看原始公告」「表達意見」。
- Demo 收尾（P1）：守護者發聲後狀態改成「保留」（`afterDemo`）。

**怎樣算做完**

- 整頁明顯標示「模擬公告」，工程名稱帶「（模擬）」，不使用真實爭議案例。

## 9. 非功能需求

### PWA 與部署

- `manifest.json`（192、512 圖示、`display: standalone`）、Service Worker、HTTPS。
- Service Worker 快取加版本號，HTML 用網路優先，避免隊友看到舊版。
- 部署到 GitHub Pages（私人 repo 改用 Cloudflare Pages 或 Vercel）。

### 效能

- 神獸圖轉成去背 WebP，每張約 100KB 以內。
- 首頁只載入地圖和 `trees.json`，其他畫面需要時再載。

### 介面與文案（照 [design-system](../../design-system/README.md)）

- 手機優先，戶外大太陽單手操作：觸控目標至少 48px、內文至少 16px、對比要夠。
- 狀態一定是「顏色＋圖示＋文字」三件一起出現。
- 廟牆紅只給「守護祂」，一個畫面只有一個紅按鈕；公示中是橘黑斜紋警報，不做成按鈕的樣子。
- 用「你」稱呼使用者，像鄰居說話；不用 emoji；不用「抽」「轉」「機率」「稀有」等抽卡用語。
- 尊重民間信仰，不畫、不鼓勵傷樹行為（釘東西、鐵絲纏繞、樹根旁燒香燒金紙）。
- 繁體中文、台灣用語、全形標點。

### 隱私

- 不要求住址、不要求登入、不蒐集兒童個資。
- 公開畫面只有守護人數，沒有名單。
- 不記錄位置與散步路線；圖鑑只有自己看得到。
- 模擬暱稱要明顯是假的（例如「早起散步的松鼠（模擬）」）。

### 資料透明與不誤導

- 真實開放資料、推估值、團隊創作、模擬資料四種要分得出來。
- 市民回報是觀察，不等於市府認定或病害診斷。
- 不宣稱已串接市府系統或已發送推播。
