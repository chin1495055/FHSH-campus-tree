# 大樹神獸：讓台北每棵樹，都有一群守護祂的鄰居

> 市政 debug 松・題目 #1「把三千棵樹種回來」｜團隊：AI 方舟計畫（Saori、Qmoa）

- **線上試玩**：https://2026-debugwithpuma.tree-god.workers.dev/ （手機打開可「加到主畫面」）
- **關於這個作品**：https://2026-debugwithpuma.tree-god.workers.dev/about.html
- **Demo 影片**：（YouTube 連結待補）

這是黑客松作品，不是市府官方服務，也沒有串接市府系統。畫面上的守護人數、回報、異動公告都是**模擬資料**，詳見下方「[資料來源](#資料來源真實開放資料與模擬資料)」。

## 一句話

用遊戲的方式守護家附近的樹：每棵樹都有一群鄰居看著，樹要被移除前大家都會知道，誤砍就不容易發生。

> 新加坡讓每棵樹都有身分證，我們讓每棵樹都有一群鄰居。

## 為什麼做這個

- 台北 2024 年移除 1,425 棵樹，2025 年移除 3,164 棵。**市府說明**八成以上是病蟲害、自然死亡或天災，近兩年也新增超過 1.3 萬棵樹。
- 中研院沈聖峰團隊的[台北樹冠觀測](https://taipei-tree-cover.pages.dev/)用衛星計算，可判讀範圍內的樹冠 2024→2026 淨減 13.73 公頃。衛星分不出是砍、移植、修剪還是颱風，成因要靠現地資料確認。
- 東門市場附近一棵約 40 年的茄苳，原本計畫移植保留，卻被廠商誤砍；有紀念樹移除約半年後才被民眾發現。

「哪裡有樹、哪裡能種、砍了多少」已經有人做了（Tree Radar、台北樹跡、台北樹冠觀測等）。我們想處理的是**為什麼會誤砍**：樹平常沒人看著，異動時沒人知道，工程現場沒人即時發現。

小樹的樹冠要很多年才長得回來，所以**先守住現有的大樹**，比事後補種更重要。

來源整理在 [data/research/背景事件整理.md](data/research/背景事件整理.md)。

## 怎麼玩

1. **找到樹**：打開就是地圖，或掃樹上的 QR code 直接打開那棵樹。老樹會化身「大樹神獸」，有名字、個性和故事。
2. **守護祂**：選「在地守護」（家附近、常經過）或「遠端關注」（人在遠方也能收到消息）。
3. **回報樹況**：拍照，勾選看得到的狀況（根盤隆起、樹幹網狀格紋、枝葉稀疏、施工公告、樹穴被填），點亮一盞燈。表單會引導市民注意褐根病的早期徵兆。
4. **樹出事時一起發聲**：樹進入移除公示，守護者都會收到異動警報，看得到原因分類、管理單位和意見截止日，可以分享「這棵樹需要你」號召更多人。

### 使用小提醒

- **相機權限**：掃描和回報拍照會請你允許使用相機。iPhone 的 Safari 預設只在這次瀏覽有效，下次打開會再問一次，這是瀏覽器的設定，不是故障。不想每次都按，可以在 Safari 網址列左邊的「網站設定」把「攝影機」改成「允許」。按「不允許」也沒關係，回報頁會改成「打開相機」按鈕，用手機內建的相機拍照。
- **電腦版**：電腦沒有掃描功能，其他功能和手機版相同，回報時可以上傳照片。
- **資料只存在這台裝置**：守護的樹、回報和照片都存在你的瀏覽器裡。換手機、換瀏覽器或清除網站資料，紀錄就不會跟著過去。

### 隱私設計

- 不用登入、不問住址、不蒐集兒童個資。
- 公開畫面只顯示守護人數，不顯示是誰在守護。
- 不記錄位置與散步路線；上傳照片前移除照片裡的位置資訊。
- 所有操作只存在自己手機的瀏覽器（localStorage、IndexedDB），不會上傳。

## 技術

純前端靜態網站，不做後端、不用建置工具。

- 原生 JavaScript（ES modules）＋ hash 路由（`#/tree/樹號`）
- Leaflet 地圖 ＋ OpenFreeMap 向量底圖
- 資料放靜態 JSON，使用者操作存 localStorage，照片存 IndexedDB
- PWA：[manifest.json](manifest.json)、[sw.js](sw.js)，可以加到手機主畫面
- 部署：Cloudflare Workers（https://2026-debugwithpuma.tree-god.workers.dev/ ，設定在 [wrangler.jsonc](wrangler.jsonc)）

### 本機執行

```bash
python -m http.server 8000
```

打開 http://localhost:8000/ 。不能直接雙擊 index.html，瀏覽器會讀不到 JSON。

## 100 天落地計畫

> 如果市府上任 100 天內要落地，需要做什麼。經費與指標都是**估算**，列出假設，不是報價；標「待查證」的項目要再確認。

**試辦範圍：中正區**。和 Demo 的資料範圍一致，區內約 9,100 棵開放資料裡的樹（行道樹約 6,700 棵、公園樹約 2,400 棵，依 10/22 下載的開放資料計算）。

**原則：接上現有制度，不另起爐灶。** 市府已經有樹木 ID 與樹上的 QR code、定期巡視、「小樹保衛站」與移樹四大原因的說明。這個計畫補的是兩次巡視之間的空檔，並讓移除前的公示確實傳到在乎這棵樹的人手上。

### 負責局處

| 單位 | 在試辦裡做什麼 |
|---|---|
| 工務局公園路燈工程管理處（公園處） | 主責。提供樹木狀態與異動排程、在後台接收市民回報並回覆、把移除與移植公示同步到平台 |
| 文化局 | 提供受保護樹木名單，這些樹在平台上特別標示、異動時提高警示等級（主管機關依《臺北市樹木保護自治條例》，待查證） |
| 資訊局 | 平台資安與個資審查、和既有系統（樹木管理系統、小樹保衛站）的串接、台北通登入 |
| 中正區公所與各里辦公處 | 社區推廣：里長發起巡樹活動、在里民大會與公布欄宣傳 |
| 教育局（試辦後期） | 區內國小的戶外教學、親子圖鑑活動 |

### 需要的資料

| 資料 | 現況 | 試辦時怎麼做 |
|---|---|---|
| 樹木位置、樹種、編號 | 已開放（行道樹及公園樹木分布圖） | 直接用 |
| 樹上 QR code 的 ID | 每棵路樹都有，但不確定和開放資料的編號是不是同一套（待查證） | 前 30 天比對；是同一套就直接用，不是就建對照表 |
| 樹木狀態（正常、保留、移植、預定移除） | 公園處內部系統，沒開放 | 試辦區先每日匯出一次給平台 |
| 移除、移植公示與原因 | 有公告但分散，沒有結構化資料 | 公示時多填一份「樹號＋原因分類＋預定日期」 |
| 施工單與施工範圍 | 各工程單位各自管理 | 試辦後期先接公園處自己發包的工程，其他單位放到試辦之後 |
| 巡視紀錄 | 沒開放（待查證） | 至少開放「最後巡視日期」，讓市民知道該補哪裡 |
| 受保護樹木名單 | 文化局（待查證是否已公開） | 直接匯入 |

### 時程

| 階段 | 要做的事 | 完成的樣子 |
|---|---|---|
| **第 0～30 天：資料與平台** | 公園處、文化局、資訊局開跨局處會議，指定窗口；比對 QR code ID 和開放資料編號；把黑客松 MVP 加上後端、台北通登入、內容審核與公園處後台（試辦期間維持 PWA：掃樹上的 QR code 直接開網頁，不用先下載 App）；完成個資與資安審查 | 中正區的樹都能在平台上查到，承辦人看得到市民回報 |
| **第 31～60 天：試辦上線** | 先找 3～5 個里（里長有意願、有公園或老樹的里）試用；掃樹上的 QR code 就能打開這棵樹的頁面；移除前公示同步通知守護者；公園處承諾回報的回覆天數 | 市民可以守護、回報，公示會通知到人 |
| **第 61～100 天：擴大到全區與檢討** | 擴大到中正區所有里；舉辦社區巡樹日與大樹公生日活動；接上公園處自己發包的工程；第 100 天公開試辦成果報告，決定要不要推到其他區 | 有成果數據可以決定是否全市推動 |

| 項目 | 估算 | 假設 |
|---|---|---|
| 平台正式化（後端、登入、審核、承辦後台） | 150～300 萬元 | 委外或資訊局自建，約 3 人 × 3 個月；前端沿用黑客松 MVP |

| 補掛 QR code 樹牌 | 0～50 萬元 | 行道樹已有 QR code 就不用；公園樹若沒有，約 2,400 棵 × 每片 100～200 元 |
| 社區推廣（活動、印刷、說明會） | 30～60 萬元 | 中正區約 31 個里（待查證），每里一場巡樹活動加文宣 |
| 公園處回應市民回報的人力 | 既有人力調配，或約聘 1 人約 15 萬元 | 100 天份；回報量大時再增加 |
| **合計** | **約 200～435 萬元** | |

### 推廣計畫

- **入口用現有的 QR code**：樹牌旁加一張小貼紙「掃我，認識這棵樹」，路過的人就是第一批使用者。
- **里長帶頭**：試辦里的里長發起第一場巡樹活動，在里民大會和公布欄宣傳。比的是「我們里守護了幾棵樹」，不做個人排名。
- **親子**：和區內國小合作戶外教學，帶小孩收集樹種圖鑑、幫樹取名字。小孩不註冊帳號，由家長操作。
- **社群分享**：每棵樹都有分享卡，樹有異動時可以分享求救卡；公示資訊附上市府的原因說明，避免變成謠言。
- **老樹故事**：請長輩說老樹的故事，整理成神獸的來歷，在大樹公生日活動公開。

### 試辦成效指標（第 100 天檢討用）

| 指標 | 試辦目標（估算） |
|---|---|
| 中正區有人守護的樹 | 1,000 棵以上 |
| 胸徑 80 公分以上的大樹有人守護的比例 | 80% 以上（區內行道樹約 68 棵） |
| 市民回報到公園處第一次回覆 | 7 天內 |
| 移除、移植公示有通知到守護者 | 100% |
| 試辦期間發生「誤砍」 | 0 件 |

### 之後可以再做（這次沒做）

參拜大樹神獸、社區共同目標、樹友留言板、樹種圖鑑、市府端查詢（工班掃樹號，狀態是保留或移植就鎖住不能移除）、散步路線留下綠意、社區樹蔭分數與補種地點、擴大到全台、真的推播與帳號系統。

**正式 App（或併入台北通）**：試辦結束後，如果要用到背景定位（散步路線）、更穩定的推播，或推到全市，再評估做原生 App，或把功能放進台北通。
