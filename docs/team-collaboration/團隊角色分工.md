# 團隊角色分工：防誤砍系統

> 市政 debug 松（2026/10/23 線上小聚、10/24 現場黑客松、10/24–10/31 線上票選）
>
> 用法：一起討論後，在「負責人」欄填上名字認領。

## 比賽的兩個關鍵

1. **沒有評審，前三名靠線上票選**：作品能不能被看見、被轉傳，和功能本身一樣重要。
2. **必須是能動的 MVP，Demo 只有約 2 分鐘**：README 還要寫「市府上任 100 天內怎麼落地」（局處、資料、成本）。

## 角色認領

| 角色 | 做什麼 | 這場的重要性 | 負責人 |
|---|---|---|---|
| 產品負責人（PO） | 定義問題、決定做什麼和不做什麼、12:00 後擋下新增功能 | 很重要，現場只有 5.5 小時 | Saori |
| UX/UI 設計 | 畫面流程、讓人一看就懂 | 中等，vibe coding 能補一部分 |Claude |
| 開發（前端、後端、資料） | 做出來、整理資料、部署上線 | 必要，沒有能動的 MVP 不算數 |Saori |
| 測試（QA） | 用使用者的角度操作、找 bug | 中等，Demo 掛掉就前功盡棄 |Qmoa + Saori|
| 政策／落地規劃 | 負責局處、需要的資料、成本、100 天推動計畫 | 這場特有，README 必寫 | Qmao + Saori|
| 簡報與 Demo 講者 | 寫 2 分鐘腳本、上台講故事 | 很重要 | 一起討論、Qmoa 講 |
| 行銷／社群拉票 | 作品名稱、懶人包、短影音、社群擴散 | **這場最關鍵**，前三名靠票數 | Saori + Qmoa |

## 要補的知識：第一線的實際流程

系統要擋的是砍樹或移植的實際流程（施工單怎麼發、工班拿到什麼、監工做什麼），要先弄清楚。

| 工作 | 負責人 |
|---|---|
| 找熟悉這個流程的人聊 15 分鐘（里長、護樹團體、景觀工程業者、公園處相關人員） | |
| 10/23 線上小聚時詢問有沒有熟悉這個領域的人 | |
| 找不到人的話，從市府新聞稿、議會質詢紀錄和相關新聞整理出流程圖 | |
